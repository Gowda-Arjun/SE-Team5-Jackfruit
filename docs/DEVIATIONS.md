# Deviations from SRS v1.0, SAD v1.0 and Test Plan v1.0

Deliverables Part-2 (2i) requires deviations to be documented and explained at the final demo.

| # | Document / section | What the document says | What we did | Why |
|---|---|---|---|---|
| D1 | SAD 3.6, STP 6 (tools) | CI/CD with Jenkins (+ SonarQube stage) | GitHub Actions (lint, migration check, tests on PostgreSQL 15) | Course Deliverables Part-2 (2b) requires GitHub Actions; no Jenkins server needed |
| D2 | SAD 1.2, 4.6; STP 7 | Three sprints (optional REST API / Technician role in Sprint 3) | Two sprints (19-23 Oct, 26-30 Oct) | Course defines exactly two sprints. REST API and Technician sub-role are out of scope unless time permits |
| D3 | Deliverables Part-2 sprint dates | Sprint 1: 19-23 Oct, Sprint 2: 26-30 Oct | Sprint 1 completed 28 Oct. Sprint 2 feature PRs merged through mid-November (last: HMS-30, #70); development frozen after HMS-36/HMS-37 | Team started late and Sprint 2 items depended on Sprint 1 models; scope unchanged, all 37 backlog items delivered |
| D4 | SAD ADR-03 | PostgreSQL in every environment incl. local dev | PostgreSQL in CI and Docker Compose; SQLite fallback for quick local runs when `POSTGRES_DB` is unset | Lets every member run the app without Docker. CI still enforces PostgreSQL behaviour |
| D5 | SAD 3.6 | Python 3.11 | Python 3.12 | Current stable version on team machines; no API differences for Django 5.1 |
| D6 | SAD 3.4 (Nginx/Gunicorn) | Staging VM behind Nginx + Gunicorn with TLS | Demo runs on Django dev server / Docker Compose | No staging VM within the timeline; HTTPS settings covered by HMS-SR-001 settings and `check --deploy` |
| D7 | Deliverables 2g/2h, 3b | Separate Sprint 1 demo video (HMS-20, 1 min) and Sprint 2 demo video (HMS-37, 2 min) | One combined final demo video (HMS-37, 2:20, `docs/videos/final_demo.mp4`): Part 1 = Sprint 1 (0:00-0:58), Part 2 = Sprint 2 (0:58-2:20); HMS-20 closed as merged into HMS-37 and its story point moved to HMS-37 | Team decision: Sprint 1 finished late (D3), so a separate Sprint 1 recording would show an incomplete build days before the final one |
| D8 | SAD ADR-05 | Razorpay payment gateway | ADR-05 (gateway) decided: Razorpay test mode, with a mock gateway as the default for development and CI. | The mock gateway supports local development and CI without live payment credentials |
| D9 | HMS-NF-001 / TC-Perf-01 | 200-user Locust run p95 <= 2 s | The local SQLite/Django development-server run recorded a 6.2 s aggregate p95 and 7.3% failures under concurrent login load | SQLite serializes concurrent writes and is only the documented local fallback; CI and Docker Compose use PostgreSQL. The attached report is indicative of this development environment, not a production capacity result |
| D10 | SRS HMS-F-001 | User registers and logs in | No public self-registration page: Admin creates student accounts (HMS-10) and `seed_demo` creates demo accounts; users then log in. TC-Auth-01 covers login and role | Hostel residents are known to the institute, so Admin-created accounts avoid unverified sign-ups (SRS lists institute ID verification as a dependency). AC-F-001 (valid credentials give a session with the correct role) is met |
| D11 | SAD 4.6 open issue (PDF library) | Choose ReportLab or WeasyPrint | ReportLab for report exports (HMS-33) and receipts (HMS-29) | Pure Python, no system libraries needed on Windows or CI |
| D12 | SAD 3.6 / 3.7 (audit retention) | Monthly partitions; older partitions exported to compressed archives | `archive_audit` exports rows older than 3 years to `.jsonl.gz`; `restore_audit` restores them. No partitioning, and rows are not purged | The audit table is append-only (HMS-SR-004), and a semester's data volume does not need partitions |
| D13 | STP 6 / 8 (test tools) | Selenium system suite, Postman collection, OWASP ZAP, testssl.sh, coverage per Jenkins run, test cases under `/docs/test-cases` | pytest + Django test client for unit, integration and security cases; system tests (ST_01-ST_33) driven in a real browser with Playwright instead of Selenium (`docs/test-evidence/system/`); Bandit, pip-audit and code review instead of ZAP; coverage.py run at freeze; test cases are documented in `docs/UNIT_TEST_REPORT.md` and `docs/SYSTEM_TEST_REPORT.md` instead of `/docs/test-cases` | Same behaviour checked with one tool chain that runs in CI on every PR; Playwright drives the same browser journeys as Selenium without a separate driver binary; no staging host for ZAP/testssl (D6). Results in `docs/TEST_REPORT.md` |
| D14 | STP TC-Sec-12 | Repeated failed logins and OTP requests are throttled | No login or OTP rate limiting. OTPs are hashed, single-use and expire in 10 minutes, and the reset form gives a generic response for unknown emails | Not in any SRS requirement or backlog item; recorded as a residual risk in `docs/TEST_REPORT.md` |
| D15 | SAD 3.3 (Notifier adapter) | Separate email/SMS adapter with retries | Complaint notifications use Django `send_mail` after commit; failures are logged, never raised. Console email backend in development | Same behaviour (a failed notification never rolls back data) with less code; SMS out of scope |
| D16 | SRS 4.5 (reports for Admin) | Reports for Admin | Reports open to Admin and Warden | SRS 2.3 groups Warden/Admin as one role for management tasks |
| D17 | SAD 2.3 (Technician role optional) | Technician role built only in Sprint 3 if time permits | Technician sees and updates only the complaints assigned to them; assignment is done in Django admin | Small addition on top of HMS-F-031; no separate Technician UI |
| D18 | SAD 4.4 (logging) | Structured JSON logs | Plain-text console logs with emails and phone numbers masked by `core.log_filters.MaskPIIFilter`, including Django's own request loggers | Masking is the data-protection requirement (HMS-NF-003); JSON format adds no value without a log server |
